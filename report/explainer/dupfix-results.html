Can GPT-4.1 stop repeating itself?

GPT-4.1 wasted about four in ten of its proposals on cells it had already tried. We tested two fixes, with the questions and the pass marks written down before any paid run. Neither fix worked, and with the full budget the LLM came out worse than every non-LLM search.

The test in brief

If we tell GPT-4.1 what it has already tried, and ask again when it repeats itself, does it stop wasting proposals and find better designs?

Why we ran it

In the original runs, 42.7% of GPT-4.1's proposals were cells already evaluated, so a search meant to test 270 cells only tested about 145. That made the comparison with the non-LLM searches unfair to the LLM: they always used their full 270. This test gives the LLM the help it was missing.

The two arms

Arm A: history + re-prompt

The prompt lists up to 45 cells already evaluated in the niche. If a reply has repeats or broken cells, the model is told why each was rejected and asked again, up to 5 times. It never gets random cells as padding. Budget: 270 evaluations.

Arm B: history only

The same list in the prompt, nothing else. The paper's 120 API calls. This isolates the effect of showing the history.

Both arms ran GPT-4.1 on CIFAR-10 on all six devices, one search per device. We compared them with four non-LLM searches run 10 times per device: PEA with refill (random edits to the best cells, the main comparator), random sampling, NSGA-II and regularised evolution.

How to read the verdicts

Better or Worse means the LLM beat or lost to a control by more than that control's own seed-to-seed noise (the margin), or consistently across devices (sign-flip test, p ≤ 0.05). Parity means neither. The rules were fixed before the paid runs and were not changed after.

"Evals" is the number of distinct cells evaluated. "Dup." is the share of all proposals that repeated an evaluated cell; for arm A this includes proposals made on retries.

  • Arm A filled more of the budget, but not enough. It reached 231–251 evaluations, never 265. After five retries, 161 slots across the six searches were still empty.
  • Re-prompting made repeats more common. Told that a cell was already evaluated, GPT-4.1 often proposed it again or proposed another evaluated cell. Of 373 retry proposals on Edge GPU, only 75 were usable.
  • The history list helped a little. Arm B cut duplicates from 42.7% to 35.9% and evaluated 164 cells instead of 145. That is a real drop, but short of the 10-point target.
What it means

Telling the model what it has already tried is not enough to stop it repeating. The problem sits in the model's proposals, not in missing information.

One caveat, set in advance

Because arm A never reached 270 evaluations, the pre-registration says Q2 is reported but not answered by this test. We cannot say whether GPT-4.1 with a full budget would lose. We can say that with these fixes it does not get a full budget, and with what it gets it loses to all four controls.

What it means

Showing the history is cheap ($0.08 more per search) and probably helps a little, mainly by freeing more of the budget. It does not close the gap to the non-LLM searches.

6Conclusion

What this means for the paper

  • The main finding holds, and it is now harder to explain away. GPT-4.1 does not beat simple non-LLM searches that use the same predictor and the same niches. A natural objection was that it was handicapped by wasted proposals. We gave it the obvious fixes and it still lost.
  • Repeating is a property of the model's proposals. GPT-4.1 repeats cells even when the list of evaluated cells is in front of it and even after being told a cell is a repeat.
  • The fixes are not worth their cost. Re-prompting nearly tripled the cost per search ($2.35 against $0.84) and lowered the scores against the controls.
  • This is a pre-registered negative result. The paper reports it with the same prominence a positive result would have had, as the pre-registration promised.
In one sentence

Helping GPT-4.1 avoid repeats made it use more of its budget but did not make it a better search, and with the full budget it lost to every non-LLM search we ran.
